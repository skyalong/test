好，我们来详细走一遍 GitHub Actions 的流程。这应该是目前最省心的方法，把你的代码推到 GitHub，它就能在云端自动帮你打包成 APK。

整个过程主要分三步：准备你的项目文件、配置 GitHub Actions 的自动化脚本、然后推送代码触发打包。
📂 第一步：整理你的项目文件夹

在开始之前，请确保你的项目根目录（比如叫 price_app）里包含以下文件：

    main.py：你提供的完整代码。

    buildozer.spec：Buildozer 的配置文件，这是打包的核心。

    其他资源文件：比如 icon.png 之类的图片文件。

buildozer.spec 文件的关键配置：请检查或修改你的配置文件，以下内容至关重要：
ini

[app]
# 应用标题
title = 仪器检校价格系统
# 包名，格式通常是 com.<domain>.<name>
package.name = pricequery
package.domain = com.yourcompany

# 源代码和依赖
source.dir = .
source.include_exts = py,png,jpg,kv,atlas

# 关键！声明你的所有依赖，不要指定过新的Python版本
requirements = python3,kivy==2.3.0,kivymd==1.1.1,plyer,openpyxl

# Android SDK 和 NDK 版本，设置稳定版本
android.api = 33
android.ndk = 25c
android.minapi = 21

# ... 其他选项保持默认或按需调整

    注意：根据你的代码，requirements 里不需要 sdl2_image，因为 Kivy 本身会处理 SDL 依赖。同时，不要指定 python3==3.11.9 这样的具体小版本，让 Buildozer 在云端自动选择兼容版本。

⚙️ 第二步：添加 GitHub Actions 自动化脚本

在你的项目根目录下，创建 .github/workflows/build-apk.yml 文件，并填入以下内容。这个 YAML 文件就是告诉 GitHub 的服务器要执行哪些操作。
yaml

name: Build Kivy APK

on:
  push:
    branches: [ main ]  # 当你推送到 main 分支时触发
  workflow_dispatch:    # 也支持在 GitHub 网页上手动触发

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      # 1. 拉取你的代码
      - name: Checkout repository
        uses: actions/checkout@v4

      # 2. 设置 Python 环境
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.9'  # 选择一个稳定的版本

      # 3. 安装系统依赖 (Buildozer 编译所需)
      - name: Install system dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y git zip unzip openjdk-17-jdk python3-pip autoconf libtool pkg-config zlib1g-dev libncurses5-dev libncursesw5-dev libtinfo5 cmake libffi-dev libssl-dev

      # 4. 安装 Buildozer
      - name: Install Buildozer
        run: pip install buildozer

      # 5. 核心步骤！使用 Buildozer 编译 APK
      #    这里使用了社区维护的 Buildozer Action，让整个过程更可靠[citation:7][citation:8][citation:10]
      - name: Build APK with Buildozer
        uses: ArtemSBulgakov/buildozer-action@v1
        id: buildozer
        with:
          # 指定 buildozer.spec 所在目录，如果它在根目录就是 "."
          workdir: .
          # 使用稳定版 Buildozer
          buildozer_version: stable
          # 执行的命令，-v 可以输出更详细的日志
          command: buildozer -v android debug

      # 6. 保存编译好的 APK 文件
      - name: Upload APK artifact
        uses: actions/upload-artifact@v4
        with:
          name: price-app-apk
          path: ${{ steps.buildozer.outputs.filename }}

    额外说明：actions/upload-artifact@v4 是 GitHub 提供的一个标准操作，用于保存构建过程中生成的文件。如果以后你需要为 Google Play 构建签名的正式版（Release）APK 或 AAB，就需要准备密钥库（Keystore）并配置相应的 Secrets，这里我们先完成调试（Debug）版打包。

🚀 第三步：推送并触发编译

    将你的项目文件夹初始化为 Git 仓库（如果还没有），并把所有文件提交。
    bash

    git init
    git add .
    git commit -m "添加项目源码和GitHub Actions配置"

    在 GitHub 上创建一个新的仓库（Repository），然后按照提示将本地代码推送到 GitHub。
    bash

    git remote add origin https://github.com/你的用户名/你的仓库名.git
    git branch -M main
    git push -u origin main

    推送成功后，进入你的 GitHub 仓库页面，点击上方的 "Actions" 选项卡。你应该能看到名为 "Build Kivy APK" 的工作流正在运行。点击它，就可以查看详细的编译日志。整个编译过程大约需要 10-20 分钟。

    编译完成后，在同一个页面的底部，你会看到一个名为 "Artifacts" 的区域，里面就有你需要的 price-app-apk 文件，下载解压后就能得到 .apk 安装包。

💎 总结与提醒

这个方法把你的电脑从繁重的编译任务中解放出来，完全在 GitHub 的云端服务器上完成。你不需要再担心本地网络、环境配置或各种奇怪的报错。

    关于 buildozer.spec：这个文件很关键。如果打包失败，80% 的问题都出在它的配置上，特别是 requirements 部分。

    网络问题：GitHub Actions 的服务器网络环境很好，可以顺畅地下载所需的 Android SDK、NDK 以及各种依赖包，这也是我们选择它的最主要原因。
